# AGENTS.md — opencode-db-exporter

Bash+python tool to read, back up and export the local opencode SQLite database. Never write to
the opencode DB: all access uses `mode=ro` (bash: `file:$DB?mode=ro`; python: `sqlite3.connect(f"file:{db}?mode=ro", uri=True)`).

## Commands that MUST be run after editing code

```bash
# Shell syntax (every script has #!/usr/bin/env bash)
for f in src/*.sh src/menu/*.sh install.sh uninstall.sh tests/*.sh; do bash -n "$f"; done

# Python
python3 -m py_compile src/exportlib/*.py src/shrinklib/*.py

# Smoke tests against a fake DB (never touches real data)
bash tests/export_smoke.sh        # must report 0 FAIL
bash tests/menu_flow.sh           # fzf menu logic (fzf stubbed) -> must report 0 FAIL
```

When flags change (`exportlib/flags.py` for exports, `shrinklib/flags.py` for shrink — each is the SSoT), regenerate BOTH artifacts and validate:
```bash
python3 scripts/generate_schema.py                 # rewrites generated/{presets,shrink}.schema.json
python3 scripts/generate_schema.py --docs          # rewrites generated/{flags-table,shrink-flags-table}.md
python3 tests/validate_schema.py generated/presets.schema.json presets.json
python3 tests/validate_schema.py generated/shrink.schema.json shrink-presets.json
```
The schema/table artifacts in `generated/` are dev/deploy-only: the tool never reads them
at runtime, so `install.sh` now ships only `src/` (plus `uninstall.sh`/`LICENSE`) and the
smoke suite runs from the checkout, not the prefix.

## Structure

- `src/opencode-db.sh` — CLI dispatcher: `status | version | list | info | digest | backup | backups | export | exports | shrink | shrinks | deps | menu | help` (`compactions` is the deprecated alias of `digest`). Accepts a global `--from-backup <file>` (before the subcommand) that sets `OCED_FROM_BACKUP` so every read command uses a stored backup as source. Sources common.sh + view.sh + backup.sh + export.sh + exports.sh + deps.sh; menu.sh is sourced on demand.
- `src/common.sh` — config (`OPENCODE_DB`, `OCED_OUT`, `OCED_BACKUP_DIR`, `OCED_CONF`, `OCED_ACTIVITY_LOG`, `OCED_FROM_BACKUP`, `OCED_PRESETS`, `OCED_SHRINK_PRESETS`, `OCED_TZ`, `OCED_VERSION`, plus `OCED_REPO_ROOT`/`OCED_HOME_CONF_DIR`/`OCED_PORTABLE` for portable mode, and `OCED_BIN`/`OCED_PREFIX` — the install shim/prefix, overridable so tests never touch `$HOME`; `oc_is_installed` = the shim `$OCED_BIN` exists, which gates the menu's Install/Uninstall row) and helpers `o_q`, `o_die`, `o_ts`, `o_now_utc`, `o_check_deps`, `o_resolve_db`/`o_effective_db` (memoized: resolves live DB or backup, gunzips `.gz` to one temp file), `o_cleanup_tmp`, `o_backup_aligned [file] [-v]` (no file = the LAST manifest entry, the default every caller wants; `file` = that specific entry, so `backups view` can date-stamp a copy that is not the newest; `-v` adds the counts), `o_human_size`/`o_human_iso`/`o_human_ms`, and `o_local_ts <"YYYY-MM-DD HH:MM:SS"[ " UTC"|"Z"]> [fmt]` (the ONE display-timezone converter: UTC wall-clock -> the display zone, system `TZ` by default, `OCED_TZ` override; MENU PICKER ROWS ONLY, everything else — CLI, reports, files — stays UTC; garbage passes through). `o_q` is ALWAYS readonly: `sqlite3 "$(o_db_uri)"`. `load_conf` snapshots env vars BEFORE sourcing `$OCED_CONF` (env > conf) for `OPENCODE_DB OCED_OUT OCED_BACKUP_DIR OCED_COMPRESS OCED_LOG OCED_ACTIVITY_LOG OCED_FROM_BACKUP OCED_PRESETS OCED_SHRINK_PRESETS`. **Portable mode** (`OCED_PORTABLE=1` iff the resolved `OCED_CONF` IS the repo-shipped `$OCED_REPO_ROOT/opencode-db.conf` and it exists — installs never trigger it): `o_cfg_default <file>` is the pure per-file default (`~/.config/opencode-db/<file>` if present, else the repo-shipped copy, else the home path) feeding `OCED_CONF`/`OCED_PRESETS`/`OCED_SHRINK_PRESETS`; the data dirs default to `$OCED_REPO_ROOT/{exports,backups,activity.log}` (gitignored); `load_conf` SKIPS the `chmod 600` on the repo conf (never dirty git) while a home conf still gets it. An install prefix (which ships no repo config) never goes portable.
- `src/view.sh` — status/version/list/info/compactions (reads only); helpers `o_version_block`/`o_schema_probe`/`o_deps_report`; `status` ends with "Version / schema:" + "Dependencies:" sections (and, when the manifest has one, a `Safety:` line naming the `.pre_shrink` pre-shrink copy from `preshrink_manifest_record`, followed by its freshness verdict from `o_preshrink_stale`); `list` takes `--order created-asc|created-desc|updated-asc|updated-desc` (whitelisted in `OCED_LIST_ORDERS`, default `created-asc` = unchanged; the ordering column always falls back to `time_created` as the tie-break) and `--tsv` (the MENU feed: raw `id\ttitle\tcreated\tupdated\tagent\tparent_id\tparent_title\tdirectory` — no `-column` padding, no banner, no TOK/COST, so the pickers build their own label; `--root/--filter/--order` all apply there too; the human `list --info` screen is unchanged); `version` prints tool version (opencode-db) + opencode CLI version (max `session.version`) + schema probe (`OCED_EXPECTED_TABLES`/`OCED_EXPECTED_COLUMNS`), returning non-zero when tables/columns are missing; `compactions <id> show [last|N|all]` prints the compacted-context digest from the following `mode=compaction` message. `info <id>` is a DETAIL screen: it leads with the banner `== Session (<id>) - <title> ==` (slug when the title is empty) before the raw `key = value` dump, and `[--json]` (`[2]` == `--json`) returns the `o_q -json` row instead — the banner is human-only, never printed into machine output.
- `src/backup.sh` — `sqlite3 "$DB" ".backup <snap>"` (WAL-safe), optional gzip, sha256, atomic `manifest.json` (jq), `backups list/view/verify/remove/prune`; **`backups view <file>`** prints the manifest record (created / stored+raw size / sessions+msgs+parts / newest session / source DB / sha) **AND runs the sha256 check** (`[OK]` / `[FAIL]` with both hashes / `[MISSING]`) plus the `vs live DB` line from `o_backup_aligned "$f" -v` and a `--from-backup` restore hint — the check lives in the view on purpose, so a details screen can never show a backup nobody validated; `oc_backup_sha_state <record>` prints `state<TAB>manifest-sha<TAB>file-sha` and is the ONE sha check behind both `view` and `verify` (and the pre-shrink: `shrinks preshrink` reuses it). The **pre-shrink safety copy** `shrink --swap` records is the manifest `.pre_shrink` SINGLETON (NOT a member of `.backups`, so `prune` never drops it): the storage lives here but it belongs to the **shrink domain** — `backups list/view/verify/remove` never list or accept it (`oc_backup_record` only matches `.backups`), it is shown/checked/removed by `shrinks preshrink [remove]` (see shrink.sh), and `--from-backup pre-shrink/<file>` still resolves it. Helpers kept for that: `preshrink_manifest_record`/`preshrink_manifest_set`/`preshrink_manifest_clear` (the safety-copy DIR itself is named by a local in `shrink.sh`, not a backup.sh function).
- `src/exports.sh` — the export-run manager (`exports list|view|stale|remove|prune|verify|update`; `exports_runs_find` skips `.*` temporary dirs and `<stamp>~<date>` history copies so only real runs are listed). `o_export_stale <meta> [--tag]` delegates to `exportlib/stale.py --summary` and only formats the result; `list` and `verify` pass all run metadata in one `--summary-batch` call. `exports stale <stamp> [--tsv|--json]` returns per-session `id/state/kind/updated/live_updated/title` rows, including `unverifiable` for absent or invalid timestamps. Freshness is snapshot integrity, not scope coverage; newly matching sessions are update candidates.
- `src/exportlib/` (Python package: `util.py`/`config.py`/`sanitize.py`/`presets.py`/`db.py`/`render.py`/`transcript.py`/`faithful.py`/`memory.py`/`writers.py`/`cli.py` + **`stale.py`** (the ONE per-session freshness rule: `stale_ids(records, live)` + CLI `--meta|STAMP --tsv|--json`; used by `exports stale`, `exports view`, `exports list`/`verify` batch summaries, and `update.py`; TSV includes recorded `updated` and live `live_updated`, and invalid timestamps are `unverifiable`)
- `src/shrinklib/` (Python package: `__init__.py`/`config.py`/`flags.py`/`presets.py`/`plan.py`; `py_compile` it in the mandatory suite) — the shrink mirror of exportlib, split in **two disjoint families**: **session SELECTION** (CLI flags `keep`/`older_than`/`since`/`keep_all`/`keep_sessions`/`discard_sessions` — exactly ONE per invocation, `keep`=10 by default; NOT preset keys) and **OPERATIONS** (`strip_reasoning`; the only keys a recipe may carry). **`flags.py`** is the SSoT: `SHRINK_FLAGS` (all 7) + `KEEP_RULE_KEYS` (selection) + `OPERATION_KEYS`/`SHRINK_PRESET_KEYS` (ops + the `description` meta key) + `DEFAULT_SHRINK_PRESETS` (**lean**=strip, **quiet**=prune+vacuum, each carrying its own `description`) + `RECIPE_DESCRIPTION_KEY` + `help_main_shrinks()` (the `shrink presets:` block of `opencode-db help` comes from `shrinklib/flags.py --help-shrinks`, static fallback in the dispatcher) + `usage_main_shrinks()`; `generated/shrink.schema.json` (a recipe = object with only the op keys, NO oneOf keep rule) AND `generated/shrink-flags-table.md` (two tables: selection CLI-only + operations) are generated from it by `scripts/generate_schema.py`; `config.py` has `default_shrink_presets` (env `OCED_SHRINK_PRESETS` — an EMPTY value counts as unset, else `Path("")` would resolve to the CWD — > `~/.config/opencode-db/shrink-presets.json`); `presets.py` loads/validates the file (a keep rule inside a recipe DIES pointing at the matching CLI flag; unknown keys die; strip must be bool; `description` must be a non-empty string when present) and merges it OVER the built-ins — `bake_args` maps a name to operation flags (`--strip-reasoning`), unknown → `die` + known list; `selection_lines`/`op_lines`/`rule_lines` render the human criteria and `selection_tag`/`rule_tags` the COMPACT tag of the same fact (one cell: a list row is a column — the sentence is 100+ chars of parentheticals and made every `shrinks list` row 225 chars); **`plan.py`** is the single source for the shrink menu (mirror of exportlib/plan.py): `rows` (built-ins + file recipes, `__PRESET_<name>\t<name>  <operations>`), `names`, `descr`, `description`, `plan`, `bake`, **`ops-flags <strip>`**/**`op-lines <strip>`** (a TOGGLED operation set, for the menu), `list-presets`, `rule-line <rule> [value] [strip 0|1]` (human criteria for the bash engine's final resolved rule) and `rule-tag <rule> [value] [strip 0|1]` (its compact tag — `shrink.sh` never builds those phrases itself; the value is `.selection.value` for `keep`/`older_than`/`since` and the id COUNT for the two id rules, which is why the engine records it). It has NO `selection` command anymore (the menu no longer derives a selection from a recipe). Bash calls it via `python3 "$SCRIPT_DIR/shrinklib/plan.py"` with `OCED_SHRINK_PRESETS` pinned (= `oc_shrink_py` in menu.sh). `flags.py` is self-bootstrapping (adds `src/` to sys.path) and serves BOTH `--help-shrinks` (the `shrink presets:` block of `opencode-db help`) AND `--usage` (the full `opencode-db shrink --help` text that `oced_shrink_usage` delegates to).
- `src/shrink.sh` — `oced_shrink`: a **recipe** (named OPERATIONS from shrinklib: built-ins lean/quiet + `$OCED_SHRINK_PRESETS`; the first non-flag token is baked via `shrinklib/plan.py bake` → `--strip-reasoning`; the python error is surfaced verbatim, falling back to a generic unknown-recipe hint) **or nothing** (no recipe = default selection, no operation) + raw flags `--keep N`/`--older-than DAYS`/`--since DATE`/`--keep-all`/`--keep-sessions ID[,ID]`/`--discard-sessions ID[,ID]`/`--strip-reasoning`/`--dry-run`/`--list-presets` over a copy (line 2: `set -uo pipefail`); exactly ONE keep rule applies (last one wins). The kept set is closed (a kept session keeps its parents/subagents); `--discard-sessions` removes the listed ids + their descendants (the discard set is descendant-closed, so FK-safe by construction) and prints a post-build hint with the **cascade** — `export <profile> --sessions <every id that will be dropped>` — because `--sessions` matches EXACT ids while the discard set is descendant-closed: offering the listed roots alone exported part of what was about to be deleted, and it looked like it worked. The hint also says the copy is ALREADY built (the live DB still has them, so the export is worth doing before `--swap`), and `<profile>` comes from `o_shrink_discard_profile` = `$OCED_SHRINK_DISCARD_EXPORT_PROFILE` (default `archive`), validated against `o_export_profiles` (products + preset names) so a typo is reported where the command is printed and falls back (`archive`, else the always-valid `transcript`) instead of failing inside the export. When the export actually matches (`o_shrink_discard_export <cascade-csv>`: newest run whose `.sessions_selected` = the discarded set, order-insensitive; auto-detected, no menu flag, fires on the CLI path too) the shrink.json records `discard_exported: <stamp>`, the run hints `(recorded: the cascade export is <stamp> — see: opencode-db shrinks view <stamp>)`, `shrinks view` prints `discard export:`, and the key is absent when there is no match. `o_shrink_discard_profile` ALSO asks `plan.py subagent-gaps <profile>` (tokens read across every product of a bundle) whether the profile would keep the subagents the cascade contains: `no_subagents`/`no_orphan_subagents` drop the sessions themselves and `sub: omit` empties `children_of`, so NO subagent body is written while the run still reports plausible counts — all three are silent successes, i.e. the exact failure this offer prevents, so the resolver warns before the y/N gate (a warning, never a veto: excluding subagents on purpose is legitimate). A product keyword can never gap, so `archive` is silent for free. It is a CONFIG choice, not a menu row, and NOT a shrink-recipe key (recipes are ops-only). shrink.json records criteria/counts/per-table `removed`/`stripped_reasoning`/integrity + `selection` (JSON `{"rule": "keep_sessions", "ids": [...]}` — a discard ALSO carries `.selection.cascade` = the listed ids closed over their descendants: the evidence `shrinks verify`'s live coverage check reads, because after `--swap` the live DB can no longer re-expand it) + `sessions.max_updated` (the copy's newest `session.time_updated`, needed by the stale check). The rest of the pipeline is unchanged: prunes session-bound tables (message/part/todo/session_message/session_share/session_context_epoch/session_input) + `event`/`event_sequence` aggregates (`aggregate_id LIKE 'ses_%'`); optional strip-reasoning removes `part` rows whose `data` JSON has `type=reasoning`; then `integrity_check` (ok) + `foreign_key_check` (0 rows) BEFORE storing `opencode.shrunk.db`. The human `criteria` line + the `--help` block are single-sourced in python (`plan.py rule-line` / `flags.py --usage`). The engine's own block is named by mode: `== shrink plan (read-only; nothing written) ==` on a dry run (it IS a plan) vs `== shrink run (criteria and counts of THIS copy) ==` on a real one — the menu wizard prints its own `-> shrink plan` (live-DB counts) right before its y/N, so an identical second `== shrink plan ==` read as the same plan being asked twice. `--swap [--yes]` (opt-in, incompatible with `--dry-run`) replaces the LIVE DB via `oced_shrink_swap`: aborts if a process cmdline mentions `opencode` (pgrep, excluding the tool itself), re-verifies the copy read-only, snapshots the live DB with `sqlite3 .backup` to `$OCED_BACKUP_DIR/pre-shrink/opencode.pre-shrink-<ts>.db` (keeps only the most recent copy) and, on success, registers it as the manifest `.pre_shrink` singleton (the rollback of the last swap, refreshed on every swap — STORAGE is in backup.sh but it belongs to the shrink domain: `shrinks preshrink` shows/checks it and `shrinks preshrink remove` deletes it, never a `backups` surface; `--from-backup pre-shrink/<file>` still resolves it; a rollback consumes the file, so nothing is registered), swaps with an atomic `mv`, drops the stale `-wal`/`-shm` and rolls back if the new DB fails `integrity_check`. `--swap` is the ONLY path that writes the live DB, and only on explicit request. **`oced_shrinks`** — manager of the produced copies: `shrinks list [--tsv]|view <stamp> [--json]|verify [--tsv] [--yes]|remove <stamp> [--yes]|prune <N>|preshrink [--json|remove [--yes]]` over `$OCED_BACKUP_DIR/shrink/<stamp>/` (`--tsv` emits the TSV `stamp<TAB>display` rows = the single source for the menu picker; `shrinks_runs_find [asc|desc]` lists the run dirs, newest first by default). `shrinks preshrink` is the SHRINK-side home of the pre-shrink safety copy (`oced_shrinks_preshrink`): `show` (`--json` = the raw manifest record) prints file/created/size/content/source + the sha256 check (`oc_backup_sha_state`) + a freshness verdict (`o_preshrink_stale`); `remove [--yes]` deletes the file and clears `.pre_shrink` (a machine with no swap prints the "no pre-shrink" line, rc 1 only for `remove`). **TWO screens, two widths**: `list` is a COLUMN — `<date>  <tag>  <kept>/<total> kept  <before> -> <after> -N%`, the tag from `plan.py rule-tag`, ONE size expression (the row used to print the sizes three times), and the copy's own state only when it is anomalous (`(swapped/no copy)`, and `(stale)`/`(unverifiable)` appended after the size when `o_shrink_stale` fails — computed from ONE live `max(time_updated)` query per list, passed down as `live_max`); `view` is a DETAIL screen shaped like `exports view` (`== Shrink copy: <stamp> ==` then `sessions:`/`size:`/`criteria:`/`reasoning:`/`date:`/`db:`/`integrity:`/`freshness:` + the per-table removals + the files; NO `selection:` line — the rule is already named by `criteria:` and the count opens the `ids (<n>):` header, so `selection: <rule> · <n> id(s)` repeated the same fact a third time) and it carries the FULL criteria sentence plus the selected ids **capped at 8** with `… N more` — the sentence and the ids are what a column cannot hold, so they live here and nowhere else. `--json` stays the machine view: `shrink.json` verbatim, byte for byte, no banner. A legacy `shrink.json` with no `.selection` falls back to its cut criteria instead of losing the cell. Stale checks live in **one** helper (plus its pre-shrink sibling `o_preshrink_stale <record> [live_max]`, the SAME rule applied to the `.pre_shrink` record: live has newer content = stale, no `max_updated` = unverifiable): `o_shrink_stale <shrink.json> [live_max]` (echoes a warning/returns 1 when the live DB has content newer than the copy — a session added or edited since it was made, not necessarily a NEW one, since the check compares `max(time_updated)` — or when a legacy shrink.json lacks `sessions.max_updated` — unverifiable is also flagged; the optional `live_max` skips its own query); `menu.sh` and `oced_shrinks_verify` call it — the swap/remove paths ask it about the ONE picked copy, while `shrinks verify` asks it about **every** copy (a `stale` `--tsv` row is keyed by that copy's stamp, and an orphan dir is reported once, as an orphan, never also as stale). Discard-export coverage lives in the sibling **`o_shrink_unexported <shrink.json>`** (silent rc0 = covered/out of scope/unknown; reason on stdout + rc1 = flagged), asked ONLY by `oced_shrinks_verify`: gate = `rule == discard_sessions` && `sessions.deleted > 0`, then the STORED `.selection.cascade` is re-matched LIVE against the exports shelf (same `o_shrink_discard_export` the engine links with), so an export made after the shrink clears the flag and `exports remove` brings it back — a root-only export of the same root is a different set and never clears it; a legacy copy (no cascade) is condemned only by a `discard_exported` stamp whose run has vanished, and no record is never a false charge. It emits the `unexported` `--tsv` row (key = the copy's stamp) and the `⚠️  Shrinks without a discard export (N of M):` human section; a non-discard copy carries no cascade in its json, so the scope is structural. Helpers `shrinks_dir`/`shrinks_runs_find` (dirs, newest first; `asc` flips)/`shrinks_stamp_human` (`YYYYMMDD-HHMMSS` → human; a 2nd `local` arg renders it in the display TZ, used only by the menu)/`shrinks_run_row <run> [live_max] [local]` (one TSV row: the compact display of the copy, stale/unverifiable tagged, `tag=` initialised because `local` does not, and `${OCED_SHRINK_PRESETS:-}` because under `set -u` a bare reference kills the subshell and silently empties the tag; `local` — menu only — renders the date in the display TZ, the CLI passes nothing so it stays UTC).
- `src/menu.sh` — fzf menu (`run_menu`/`choose_action`/`oc_fzf_sel`); root: exports/backups/shrinks/sessions/status/help (plus an explicit `Exit` row wired to `builtin:exit`, and an `Install` row when `oc_is_installed` is false, else `Uninstall` — never both; each rendered only if `$OCED_REPO_ROOT` ships the matching script) — **no `check` row, on purpose**: `status` IS the check (read-only, backup alignment, schema probe + non-zero rc on failure, deps report), so a second row would only reprint it; artifact verification is the shrinks picker's `[?] verify` plus the sha256 folded into `backups view`. **Navigation contract (guarded by tests)**: `run_menu` has NO back-stack — a picker that RETURNS hands control to the root menu, so every "go back to the list I came from" is a `continue` inside the picker's own `while true`, never a `return`. The idiom is `menu_pause "<label>" || return 0; continue` (Enter → redraw THIS list, ESC → close the submenu / main menu); the pause label says so (`Enter: back to the list · Esc: main menu`). A deep wizard (export create, shrink create) must NOT own the pause: it returns `0` = "it ran", `130` = "ESC'd out, no pause", and the frame that OWNS the list pauses and decides the destination (`[ $? -eq 0 ] || continue; menu_pause … || return 0; continue`). Report pauses are labelled after the list (`Manage exports`/`Backups`/`Shrinks`) and create pauses after the action (`Export`/`New backup`/`Shrink copy`), so they can never be confused. `oc_shrinks_swap_pick` is the exception that already owned its pause: it now RETURNS the pause rc so `__SWAP__` can propagate an ESC. Before this, the report paths used `return 0` after the pause (→ root) while the remove paths used `continue` (→ stayed), which is why Enter after a report jumped to the main menu and Enter after a confirmed removal did not. **Root header**: `run_oc_menu` passes `--refresh-cb oc_root_status` so `ACTION_STATUS` (DB/sessions/WAL/backup/exports counts) is recomputed on every root loop — never stale after an action. Pickers: **Symbol system (a contract, guarded by a test): one bracket + a token, and the token says what the row does** — `[>]` opens a FLOW (`__CREATE__`/`__SWAP__`/`__MAKE__`/`__PRESHRINK__`: create backup, create shrink copy, swap, remove the pre-shrink safety copy, choose preset, continue) **or prints the whole list at once** (`__REPORT_ALL__`: `[>] details of all sessions|runs|copies`, the one screen-vs-list row that is not a toggle — it renders the same per-row screens in one pass), `[?]` INSPECTS (`__VERIFY__`/`__EXPLAIN__`), `[*]` TOGGLES (`oc_toggle_row` is the single implementation, so the mode/order/subagent switches inherit it) and renders `[<word>]` for bulk actions (`[mark all]`, `[unmark all]`, `[delete all]`, `[delete olds]`); `[x]`/`[ ]` stay the per-session marks. A toggle row always shows BOTH states (`[*] view  →  remove`), and the flow rows that used to carry a parenthetical (what a backup copies, what a shrink does, `orphan dirs…`) dropped it — the sub-picker header or the command output says it. `oc_backups_picker`'s `__CREATE__` is **plan → OUR gate → non-interactive run** (`run_oced_tool backup --dry-run` → `confirm_action "Create this backup now?"` → `run_oced_tool_spin "Backing up" backup --yes`), the same shape as the shrink wizard, so the frame that owns the list decides and no command ever asks on stdin from inside a menu call; **the plan is printed exactly once** — `backup --yes` suppresses it (it means "the caller owns the gate AND already showed the plan"; only `--dry-run` always prints it), because re-printing it put the same block on screen twice; `oc_export_picker`'s `snapshot: fresh` offer follows the same rule (it already had a `confirm_action`, and the backup it used to launch asked a SECOND, invisible one). `oc_backups_picker` has the same two modes as exports/shrinks (`__CREATE__` first, then the `[*] view → remove` toggle, then the `[*] newest first → old first` ORDER toggle in BOTH modes, then `[delete all]`/`[delete olds]` in remove mode, then the per-backup rows): a row in view mode runs `backups view <file>` + `menu_pause` and redraws the backups list, in remove mode it deletes behind the confirmation, `oc_sessions_picker` details-only (info + digests), `oc_shrinks_picker` **create + manage in one entry** (rows `__CREATE__` first, then `__SWAP__` (destructive — pick a copy, `o_shrink_stale` warning, `oc_confirm_typed "confirm"`, `oced_shrink_swap`), then `__PRESHRINK__` = `[>] remove pre-shrink safety copy` (rendered only when the manifest `.pre_shrink` singleton exists; shows its details then confirms, never a backups row), then `__TOGGLE__` view/remove and the `__TOGGLE_ORDER__` newest/old switch (both modes), plus `__VERIFY__` = `shrinks verify` (which audits the freshness **and the discard-export coverage of every** copy, not only the newest) and `__REPORT_ALL__` = `[>] details of all copies` (view mode only); remove mode adds `__DELETE_ALL__`/`__KEEP_NEWEST__` + per-run rows — deleting a stale/unknown-freshness copy warns via `o_shrink_stale` first; selecting a row views `shrinks view <stamp>` or removes with confirmation; ## Schema rules (opencode.db)

- `session`: `parent_id` (subagent when non-empty), `agent` (build/explore/plan), `model`, `directory`, `time_compacting`, `tokens_*`, `cost`, `share_url`.
- `part.data.type` ∈ `text | file | step-start | reasoning | tool | step-finish | patch | compaction`.
- Tool call: `part.data` → `state.input.command` (tool), `state.input.arguments`, `state.output` (truncatable).
- `message.data.summary.diffs` — per-message change summary (`--summary-diffs`); `summary` can be `true` (bool), not only an object.
- Compactions: parts `type='compaction'` are only markers (`auto`, `overflow`, `tail_start_id`); the compacted-context **digest** is the `text` part of the next message with `data.mode='compaction'`.
- Session pickers must ignore the sqlite `-column` separator line (rows are filtered by `$1 ~ /^ses_/`).
- Config precedence is **environment > conf file > per-file default** (that default is `~/.config/opencode-db/<file>` if present, else the repo-shipped copy when running portably, else the built-in; `common.sh` snapshots env vars before sourcing `$OCED_CONF`). Keep it that way: never let the conf clobber an explicitly exported variable.

## Known pitfalls

- **SIGPIPE/pipefail**: never use `cmd | grep -q PATTERN` in tests or modules when `cmd` is a long-running subprocess; grep closes the pipe on match and the producer dies with 141. Capture first: `out=$(cmd); printf '%s' "$out" | grep -q PATTERN`.
- `model` may already be serialized as JSON (don't double-encode).
- Newlines inside JSON after `json_each`/diagonals are escaped before `data:json_each`; use `json_quote` for raw dumps.
- `set -euo pipefail` in bash: pipelines with `grep -q` may return 141 (see above).
- **bash `read` COLLAPSES runs of IFS whitespace**: `IFS=$'\t' read -r a b c <<< $'x\t\t\ty'` gives `a=x`, `c=` (never three fields) — so a TSV row with consecutive EMPTY middle fields (parent_id + parent_title of a root) silently swallows whatever follows (the menu feed's `directory` disappeared like this). Split on a NON-whitespace sentinel instead: `IFS=$'\x1f' read -r … <<<"${line//$'\t'/$'\x1f'}"`.
- **`local` inside a loop persists after the loop**: `local title` in a for/while body keeps that name bound (value + scope) for the rest of the FUNCTION, clobbering a same-named function variable used later (the picker's `title` cfg became the last rendered session title → the fzf prompt showed it). Loop locals are named `rid rtitle rcreated …`, never `title`/`id`.
- Local `trap` EXIT inside functions: `trap - EXIT` before `return` so the caller's trap isn't cancelled.
- **`shrink --swap`**: the EXIT trap removing `$snap` must be cleared (`trap - EXIT`) BEFORE the swap moves the snap into `$OPENCODE_DB`, or the trap would delete the live DB on exit. The swap safety copy is written to `$OCED_BACKUP_DIR/pre-shrink/` (not `$OPENCODE_DB.pre-shrink-*`); stale checks use `o_shrink_stale` on `sessions.max_updated`, which the current `shrink.json` format records — older copies without it are flagged as unverifiable.
- `o_effective_db` is memoized: `o_resolve_db` must run in the **parent** shell (the dispatcher calls it; `o_db_exists` calls it directly). Never resolve a backup only inside `$(...)` (command substitution = subshell: the decompressed temp would be re-created per call and never cleaned). The dispatcher sets `trap 'o_cleanup_tmp' EXIT` to remove the decompressed `.gz` temp.
- Paths and file names: `safe_filename` strips `@()[]` etc.

## Deploy

- `install.sh` — copies `src/` (+`uninstall.sh`, `LICENSE`) to `~/.local/share/opencode-db-exporter` (no tests/docs/`generated`/schema artifacts: the tool never reads them at runtime), symlinks `~/.local/bin/opencode-db` → `src/opencode-db.sh`, creates the conf from the shipped `opencode-db.conf` only if MISSING (permissions 600 — it is path config, never clobbered) but **REFRESHES `presets.json` + `shrink-presets.json` from the shipped files on every install** (overwritten, permissions 600): a preset added in a release (e.g. `prompts`, `review`, `rag`) only reaches the menu if the installed copy is brought up to date, and these are not path config. Customize them *after* installing (a re-install will overwrite again).
- `uninstall.sh [--all] [--yes]` — removes the installed code + shim; keeps conf/backups/exports unless `--all` (the keep-`backups`/`exports` branch uses a whitelist find under `$PREFIX`, not a reinstall list).
- Config: `~/.config/opencode-db/opencode-db.conf` (600) + `~/.config/opencode-db/presets.json` (600) + `~/.config/opencode-db/shrink-presets.json` (600). Dependencies are self-managed via `opencode-db deps`.
