# AGENTS.md — opencode-db-exporter

Bash+python tool to read, back up and export the local opencode SQLite database. Never write to
the opencode DB: all access uses `mode=ro` (bash: `file:$DB?mode=ro`; python: `sqlite3.connect(f"file:{db}?mode=ro", uri=True)`).

## Commands that MUST be run after editing code

```bash
# Shell syntax (every script has #!/usr/bin/env bash)
for f in src/*.sh src/menu/*.sh install.sh uninstall.sh tests/*.sh; do bash -n "$f"; done

# Python
python3 -m py_compile src/exportlib/*.py src/shrinklib/*.py

# Smoke tests against a fake DB (never touches real data)
bash tests/export_smoke.sh        # must report 0 FAIL
bash tests/menu_flow.sh           # fzf menu logic (fzf stubbed) -> must report 0 FAIL
```

When flags change (`exportlib/flags.py` for exports, `shrinklib/flags.py` for shrink — each is the SSoT), regenerate BOTH artifacts and validate:
```bash
python3 scripts/generate_schema.py                 # rewrites generated/{presets,shrink}.schema.json
python3 scripts/generate_schema.py --docs          # rewrites generated/{flags-table,shrink-flags-table}.md
python3 tests/validate_schema.py generated/presets.schema.json presets.json
python3 tests/validate_schema.py generated/shrink.schema.json shrink-presets.json
```
The schema/table artifacts in `generated/` are dev/deploy-only: the tool never reads them
at runtime, so `install.sh` now ships only `src/` (plus `uninstall.sh`/`LICENSE`) and the
smoke suite runs from the checkout, not the prefix.

## Structure

- `src/opencode-db.sh` — CLI dispatcher: `status | version | list | info | digest | backup | backups | export | exports | shrink | shrinks | deps | menu | help` (`compactions` is the deprecated alias of `digest`). Accepts a global `--from-backup <file>` (before the subcommand) that sets `OCED_FROM_BACKUP` so every read command uses a stored backup as source. Sources common.sh + view.sh + backup.sh + export.sh + exports.sh + deps.sh; menu.sh is sourced on demand.
- `src/common.sh` — config (`OPENCODE_DB`, `OCED_OUT`, `OCED_BACKUP_DIR`, `OCED_CONF`, `OCED_ACTIVITY_LOG`, `OCED_FROM_BACKUP`, `OCED_PRESETS`, `OCED_SHRINK_PRESETS`, `OCED_VERSION`, plus `OCED_REPO_ROOT`/`OCED_HOME_CONF_DIR`/`OCED_PORTABLE` for portable mode) and helpers `o_q`, `o_die`, `o_ts`, `o_now_utc`, `o_check_deps`, `o_resolve_db`/`o_effective_db` (memoized: resolves live DB or backup, gunzips `.gz` to one temp file), `o_cleanup_tmp`, `o_backup_aligned [file] [-v]` (no file = the LAST manifest entry, the default every caller wants; `file` = that specific entry, so `backups view` can date-stamp a copy that is not the newest; `-v` adds the counts), `o_human_size`/`o_human_iso`/`o_human_ms`. `o_q` is ALWAYS readonly: `sqlite3 "$(o_db_uri)"`. `load_conf` snapshots env vars BEFORE sourcing `$OCED_CONF` (env > conf) for `OPENCODE_DB OCED_OUT OCED_BACKUP_DIR OCED_COMPRESS OCED_LOG OCED_ACTIVITY_LOG OCED_FROM_BACKUP OCED_PRESETS OCED_SHRINK_PRESETS`. **Portable mode** (`OCED_PORTABLE=1` iff the resolved `OCED_CONF` IS the repo-shipped `$OCED_REPO_ROOT/opencode-db.conf` and it exists — installs never trigger it): `o_cfg_default <file>` is the pure per-file default (`~/.config/opencode-db/<file>` if present, else the repo-shipped copy, else the home path) feeding `OCED_CONF`/`OCED_PRESETS`/`OCED_SHRINK_PRESETS`; the data dirs default to `$OCED_REPO_ROOT/{exports,backups,activity.log}` (gitignored); `load_conf` SKIPS the `chmod 600` on the repo conf (never dirty git) while a home conf still gets it. An install prefix (which ships no repo config) never goes portable.
- `src/view.sh` — status/version/list/info/compactions (reads only); helpers `o_version_block`/`o_schema_probe`/`o_deps_report`; `status` ends with "Version / schema:" + "Dependencies:" sections; `list` takes `--order created-asc|created-desc|updated-asc|updated-desc` (whitelisted in `OCED_LIST_ORDERS`, default `created-asc` = unchanged; the ordering column always falls back to `time_created` as the tie-break); `version` prints tool version (opencode-db) + opencode CLI version (max `session.version`) + schema probe (`OCED_EXPECTED_TABLES`/`OCED_EXPECTED_COLUMNS`), returning non-zero when tables/columns are missing; `compactions <id> show [last|N|all]` prints the compacted-context digest from the following `mode=compaction` message. `info <id>` is a DETAIL screen: it leads with the banner `== Session (<id>) - <title> ==` (slug when the title is empty) before the raw `key = value` dump, and `[--json]` (`[2]` == `--json`) returns the `o_q -json` row instead — the banner is human-only, never printed into machine output.
- `src/backup.sh` — `sqlite3 "$DB" ".backup <snap>"` (WAL-safe), optional gzip, sha256, atomic `manifest.json` (jq), `backups list/view/verify/remove/prune`; **`backups view <file>`** prints the manifest record (created / stored+raw size / sessions+msgs+parts / newest session / source DB / sha) **AND runs the sha256 check** (`[OK]` / `[FAIL]` with both hashes / `[MISSING]`) plus the `vs live DB` line from `o_backup_aligned "$f" -v` and a `--from-backup` restore hint — the check lives in the view on purpose, so a details screen can never show a backup nobody validated; `oc_backup_sha_state <record>` prints `state<TAB>manifest-sha<TAB>file-sha` and is the ONE sha check behind both `view` and `verify` (like `o_shrink_stale` for shrinks).
- `src/exports.sh` — the export-run manager (`exports list|view|remove|prune`). `exports view <stamp>` is a DETAIL screen that reads **only the metadata** (`metadata.json`, legacy `metadatos.json`, found with `find`) — never `index.md`, whose markdown session table is the reason the view is unreadable. Human mode: banner `== Export run: <stamp> ==` ONCE at the top (never repeated per product), one summary line per product, the aggregate `totals:`/`date:`/`db:`/`sha256:` block (roots/subagents = max, msgs/comp = sum), then `== Details per product ==` with one field block per product. `--json` returns the raw metadata records as an array (no banner, no aggregation) and `--files` appends the produced files + sizes. Two shape rules the data forces: `.sessions_selected` is an ARRAY (`join(",")`, never `+`), and a legacy `.sessions` without `.total` derives it as `roots + subagents`.
- `src/exportlib/` (Python package: `util.py`/`config.py`/`sanitize.py`/`presets.py`/`db.py`/`render.py`/`transcript.py`/`faithful.py`/`memory.py`/`writers.py`/`cli.py` + **`flags.py`** — the single source of truth for every export flag: name/type/choices/default/products/description (CLI `--flag` form in `cli.py` (incl. the `--filter|--sessions|--last|--since` mutex group, and the CLI-only `--out`/`--last`/`--since` in `CLI_ONLY_KEYS`), presets key validation in `presets.py`, `generated/presets.schema.json` AND `generated/flags-table.md` are generated from it by `scripts/generate_schema.py`, menu annotations via `exportlib/flags.py --annotate "key=value,…"` used by `oc_annotate_flags`; the `export products:`/`export flags:` block of `opencode-db help` is emitted by `flags.py --help-exports` (products from `PRODUCT_HELP`, flags from `FLAG_HELP` in dict order — `help()` in `opencode-db.sh` calls it with a static fallback); to add/modify a flag edit `FLAGS`, then regenerate) + **`plan.py`** — the single Python place that answers "what will this export produce?" for any profile (product keyword OR named preset): `resolve()` returns the full JSON plan (products, per-product intro/flags/bits, has_json/has_sanitize, descr/purpose) and a CLI bridge (`rows`/`names`/`products` (+`--legend`)/`descr`/`purpose`/`legend`/`resolve`/`plan`/`notes`, exit 1 = nothing to produce) that runs the `menu.sh` preset helpers — `oc_preset_rows`/`oc_preset_descr`/`oc_preset_purpose`/`oc_preset_legend`/`oc_export_plan`/`oc_export_notes` are thin shells pinning `OCED_PRESETS` through `oc_plan_py` and delegating to it (no more jq in the menu; `oc_pick_product` is gone — the menu is preset-only, but `products`/`products --legend` stay as the API surface for the CLI and tests; products + plans + intros are edited in `flags.py`/`plan.py`, not in `menu.sh`); `PRODUCT_INTRO`/`PRODUCT_KEYWORDS`/`PRODUCTS` live in `flags.py`). **The plan is rendered FLAT and flush-left** — this is a tested contract, not a style preference: `plan_text()` emits one line per product at the left margin with its intro and effective flags BELOW it (`_product_block`), a blank line between products, and NO label (`Will produce:` is gone), NO bullets and NO indentation anywhere; `_wrap()` folds every line into `PLAN_WIDTH = 72` deterministically, and nothing is dropped to achieve the flatness (the full `PRODUCT_INTRO` is still printed, only wrapped). `annotate_flags()` returns a **LIST of standalone phrases** (`plan.py`'s per-item `bits`), rendered ONE PER LINE: no separator and no bullet marker, because the old `" · ".join(...)` plus a leading `+` read as an expression (`+faithful JSON… · full tool outputs`) rather than a list, and the `+` only survived because it happened to come first — both literals are gone (`PRODUCT_INTRO` lost its `—`/`+` too) and a guard fails the suite if any `^[+*-] `, ` · ` or `—` reappears in the block. A bare product keyword prints `Default options, no flags set` as its own caption (it used to hang off the description as `(default options)`, which the 72-col wrap orphaned onto its own line). The caveats are NOT products: `notes_text()` renders them in their own `-> Notes` block and returns `""` when a plan has nothing to warn about, so the menu prints no block at all; they are derived from the plan's own `has_json`/`has_sanitize`, never hand-written. The CLI exposes both halves (`plan <profile> [--width N]`, `notes <profile> [--width N]`) so `menu/export.sh` never formats anything itself; `src/exportlib/cli.py` is the self-bootstrapping CLI entry (running it directly adds `src/` to sys.path — the old `src/export.py` shim is gone; `export.sh` forwards to `python3 "$SCRIPT_DIR/exportlib/cli.py"`)) — products `transcript|memory|digest` (`full` accepted as an alias of `transcript`, `compactions` a deprecated alias of `digest`, normalised in `resolve_profile` so nothing downstream sees the old spelling); no `all` meta-profile, no `no-calls`/`text-only`; `--filter`, `--sessions ID[,ID…]` (exact session ids, `WHERE s.id IN (…)`), `--sub separate|inline|omit`, **subagent inclusion** `--no-subagents` / `--no-orphan-subagents` (both `products=["*"]`, applied to the selected set BEFORE the hierarchy is resolved; a *subagent* = non-empty `parent_id` whose parent row still exists (`all_session_ids()`), a session whose parent is gone is an *orphan* = a root and is never hidden; `--no-subagents` drops every subagent for ALL products, `--no-orphan-subagents` drops a selected subagent whose parent is not exported (fixpoint over nested chains) instead of promoting it to a root — the DEFAULT keeps it standalone, which is the "only that one subagent" use case; both die with an explanation when nothing is left; `metadata.json` gains `.no_subagents`/`.no_orphan_subagents`/`.subagents_hidden` = how many the flags actually dropped from the MATCHED set, and `index.md` only grows the `Subagents` row when a flag set it), `--tool-output full|truncated|omit`, `--patch full|omit`, `--mark-compactions`, `--summary-diffs`, `--no-reasoning`, `--role all|user|assistant` (a flag, NOT a preset; `memory` ignores it, documented in its index); `--json` (faithful archive per session, native `{info, messages:[{info, parts}]}` shape, `info.tokens.backfilled`); `--sanitize` (recursive regex redaction **in memory, on native types, before serializing** — `sanitize_json` walks `dict`/`list`/`str`; markdown sanitizes each string at render time; never post-processes the final file: high-confidence prefixes only `sk-`/`sk-ant-`/`ghp_`/`gho_`/`github_pat_`/`xox[baprs]-`/`AIza`/`AKIA`/JWT (`eyJ…`)/`Bearer`/private PEM keys (multiline, `re.S`); generic `key=value`/env-var-name patterns are deliberately EXCLUDED to avoid false positives); **`snapshot: fresh`** — a SINGLE-preset-only workflow flag (`SINGLE_ONLY_KEYS`; never per-product/bundle): the export doubles as a reference archive, so the CLI warns (`_backup_aligned` — same triple as the menu's `o_backup_aligned`) when no backup exists or the last one diverged from the live DB, and the menu offers to create a fresh backup first; skipped under `--from-backup`; **token backfill** — sessions whose `tokens_*`/`cost` row is 0/NULL get their totals summed from `part` rows `data.type='step-finish'` (`tokens.input/output/reasoning/cache.{read,write}` + `cost`), in-memory, flagged `tokens_backfilled`; `memory` adds `--cap N` (0 = unlimited, default) + `--files` (touched files from tool inputs `path/filePath/file_path` and `+++ b/` patch headers) and writes `corpus.jsonl` **streamed line by line** (one root+subagents per line, `flush()` per root — never accumulates the corpus in RAM; prints a `--cap` hint past ~50 MB with unlimited text); help `digests_for`/`touched_files` — the SAME compaction source used by `view.sh` and the `digest` product. **Named presets** — `OCED_PRESETS` JSON file is the source of truth for CLI + menu (contract: `generated/presets.schema.json`, docs: `docs/schemas.md`): `export <name>` auto-resolves (`name` = product keyword → product; else known preset → `apply_preset()` merges its keys over argparse defaults validating choices/types with `die()`; else `ap.error` lists products+presets); allowed keys `product|sub|no_subagents|no_orphan_subagents|tool_output|tool_input_limit|tool_output_limit|patch|role|no_reasoning|mark_compactions|summary_diffs|json|sanitize|cap|files` + selection `filter` (LIKE) **or** `sessions` (ids, not both); **`--last N`/`--since DATE` are CLI-ONLY selection rules** (in `CLI_ONLY_KEYS` with `out`, so the generated schema rejects them: their set changes every run, so no plan can pin one) — exactly ONE selection rule per run in one argparse mutex group (`--filter|--sessions|--last|--since`), `_pos_int`/`_iso_date` validate at the command line (`--last 0`/`abc` and a non-`YYYY-MM-DD` date are refused), `load_sessions` implements them (`--last` ranks ROOTS by `time_updated` and closes over descendants with a recursive CTE, like `shrink --keep N`; `--since` is a plain window), and `util.selection_rule()`/`selection_label()`/`selection_meta()` are the ONE description of the rule (metadata `.selection`, the `index.md` `Selection` row, the "matched nothing" error, and the `plan.py` menu queries); ***bundle presets** use `products` = `{product: {flags}}` (transcript|memory|digest, exclusive with `product`, selection stays top-level/shared) — `run_bundle()` in `cli.py` computes one shared collision-free stamp and re-executes `exportlib/cli.py <product> --stamp <shared> --preset-name <main>` per product (unchanged single-product pipeline: own index.md + metadata.json, a stamp-root index.md ties the bundle; `exports list` aggregates as `transcript+memory`). **CLI wins over the preset***: explicit `--filter`/`--sessions` clobber the whole preset selection (`cli_selection`), any explicit flag wins (`flag_in_argv`; preset keys are underscored but map to dashed flags via `_flag()`). `metadata.json` records `.preset`/`.sessions_selected` (the REQUESTED ids) and **`.session_records`** (WHICH sessions the run actually contains: one entry per written session, identity only — `id`/`title`/`kind`/`parent_id`/`created`/`updated`, no per-session counts because the totals already live at the top level). Built by `_session_records()` from the SAME `written` list of `(root, subs, folder)` tuples that created the directories, so records cannot disagree with the artifacts; `.sessions` stays the untouched aggregate (it is the summary of the records) and `.sessions_selected` keeps its own meaning. Never capped. An orphan (parent row gone) is `kind: root` with its dangling `parent_id` verbatim; absent parent is `null`, never `""`. Writes `index.md` + `metadata.json` per run (`metadata.json.role`, `.json`, `.sanitize`, `.reasoning`, `.tokens_backfilled`; memory: `.touched_files` bool + `.files` produced list — never a shared key). EVERY product also records `.compactions` (the markers opencode wrote, `part.data.type='compaction'`) AND `.digests` (the summary texts, `message.data.mode='compaction'`): two counters for two different things, never interchangeable (a marker carries no text, so markers >= digests). **Contract hardening** (docs/schemas.md): dates ISO-8601 UTC via `ts_iso` (`YYYY-MM-DDTHH:MM:SSZ`); absent values `null` in machine artifacts (corpus/faithful/metadata), `""` only in markdown; `model_str` normalizes a JSON-serialized model to its plain id (one form); corpus lines carry `schema_version: 1` (bump on breaking shape change); corpus `messages`/`tools`/`compactions` count the ROOT session only.
- `src/shrinklib/` (Python package: `__init__.py`/`config.py`/`flags.py`/`presets.py`/`plan.py`; `py_compile` it in the mandatory suite) — the shrink mirror of exportlib, split in **two disjoint families**: **session SELECTION** (CLI flags `keep`/`older_than`/`since`/`keep_all`/`keep_sessions`/`discard_sessions` — exactly ONE per invocation, `keep`=10 by default; NOT preset keys) and **OPERATIONS** (`strip_reasoning`; the only keys a recipe may carry). **`flags.py`** is the SSoT: `SHRINK_FLAGS` (all 7) + `KEEP_RULE_KEYS` (selection) + `OPERATION_KEYS`/`SHRINK_PRESET_KEYS` (ops) + `DEFAULT_SHRINK_PRESETS` (**lean**=strip, **quiet**=prune+vacuum) + `SHRINK_PRESET_PURPOSE` + `help_main_shrinks()` (the `shrink presets:` block of `opencode-db help` comes from `shrinklib/flags.py --help-shrinks`, static fallback in the dispatcher) + `usage_main_shrinks()`; `generated/shrink.schema.json` (a recipe = object with only the op keys, NO oneOf keep rule) AND `generated/shrink-flags-table.md` (two tables: selection CLI-only + operations) are generated from it by `scripts/generate_schema.py`; `config.py` has `default_shrink_presets` (env `OCED_SHRINK_PRESETS` — an EMPTY value counts as unset, else `Path("")` would resolve to the CWD — > `~/.config/opencode-db/shrink-presets.json`); `presets.py` loads/validates the file (a keep rule inside a recipe DIES pointing at the matching CLI flag; unknown keys die; strip must be bool) and merges it OVER the built-ins — `bake_args` maps a name to operation flags (`--strip-reasoning`), unknown → `die` + known list; `selection_lines`/`op_lines`/`rule_lines` render the human criteria and `selection_tag`/`rule_tags` the COMPACT tag of the same fact (one cell: a list row is a column — the sentence is 100+ chars of parentheticals and made every `shrinks list` row 225 chars); **`plan.py`** is the single source for the shrink menu (mirror of exportlib/plan.py): `rows` (built-ins + file recipes, `__PRESET_<name>\t<name>  <operations>`), `names`, `descr`, `purpose`, `plan`, `bake`, **`ops-flags <strip>`**/**`op-lines <strip>`** (a TOGGLED operation set, for the menu), `list-presets`, `rule-line <rule> [value] [strip 0|1]` (human criteria for the bash engine's final resolved rule) and `rule-tag <rule> [value] [strip 0|1]` (its compact tag — `shrink.sh` never builds those phrases itself; the value is `.selection.value` for `keep`/`older_than`/`since` and the id COUNT for the two id rules, which is why the engine records it). It has NO `selection` command anymore (the menu no longer derives a selection from a recipe). Bash calls it via `python3 "$SCRIPT_DIR/shrinklib/plan.py"` with `OCED_SHRINK_PRESETS` pinned (= `oc_shrink_py` in menu.sh). `flags.py` is self-bootstrapping (adds `src/` to sys.path) and serves BOTH `--help-shrinks` (the `shrink presets:` block of `opencode-db help`) AND `--usage` (the full `opencode-db shrink --help` text that `oced_shrink_usage` delegates to).
- `src/shrink.sh` — `oced_shrink`: a **recipe** (named OPERATIONS from shrinklib: built-ins lean/quiet + `$OCED_SHRINK_PRESETS`; the first non-flag token is baked via `shrinklib/plan.py bake` → `--strip-reasoning`; the python error is surfaced verbatim, falling back to a generic unknown-recipe hint) **or nothing** (no recipe = default selection, no operation) + raw flags `--keep N`/`--older-than DAYS`/`--since DATE`/`--keep-all`/`--keep-sessions ID[,ID]`/`--discard-sessions ID[,ID]`/`--strip-reasoning`/`--dry-run`/`--list-presets` over a copy (line 2: `set -uo pipefail`); exactly ONE keep rule applies (last one wins). The kept set is closed (a kept session keeps its parents/subagents); `--discard-sessions` removes the listed ids + their descendants (the discard set is descendant-closed, so FK-safe by construction) and prints a post-build hint with the **cascade** — `export <profile> --sessions <every id that will be dropped>` — because `--sessions` matches EXACT ids while the discard set is descendant-closed: offering the listed roots alone exported part of what was about to be deleted, and it looked like it worked. The hint also says the copy is ALREADY built (the live DB still has them, so the export is worth doing before `--swap`), and `<profile>` comes from `o_shrink_discard_profile` = `$OCED_SHRINK_DISCARD_EXPORT_PROFILE` (default `archive`), validated against `o_export_profiles` (products + preset names) so a typo is reported where the command is printed and falls back (`archive`, else the always-valid `transcript`) instead of failing inside the export. `o_shrink_discard_profile` ALSO asks `plan.py subagent-gaps <profile>` (tokens read across every product of a bundle) whether the profile would keep the subagents the cascade contains: `no_subagents`/`no_orphan_subagents` drop the sessions themselves and `sub: omit` empties `children_of`, so NO subagent body is written while the run still reports plausible counts — all three are silent successes, i.e. the exact failure this offer prevents, so the resolver warns before the y/N gate (a warning, never a veto: excluding subagents on purpose is legitimate). A product keyword can never gap, so `archive` is silent for free. It is a CONFIG choice, not a menu row, and NOT a shrink-recipe key (recipes are ops-only). shrink.json records criteria/counts/per-table `removed`/`stripped_reasoning`/integrity + `selection` (JSON `{"rule": "keep_sessions", "ids": [...]}`) + `sessions.max_updated` (the copy's newest `session.time_updated`, needed by the stale check). The rest of the pipeline is unchanged: prunes session-bound tables (message/part/todo/session_message/session_share/session_context_epoch/session_input) + `event`/`event_sequence` aggregates (`aggregate_id LIKE 'ses_%'`); optional strip-reasoning removes `part` rows whose `data` JSON has `type=reasoning`; then `integrity_check` (ok) + `foreign_key_check` (0 rows) BEFORE storing `opencode.shrunk.db`. The human `criteria` line + the `--help` block are single-sourced in python (`plan.py rule-line` / `flags.py --usage`). The engine's own block is named by mode: `== shrink plan (read-only; nothing written) ==` on a dry run (it IS a plan) vs `== shrink run (criteria and counts of THIS copy) ==` on a real one — the menu wizard prints its own `-> shrink plan` (live-DB counts) right before its y/N, so an identical second `== shrink plan ==` read as the same plan being asked twice. `--swap [--yes]` (opt-in, incompatible with `--dry-run`) replaces the LIVE DB via `oced_shrink_swap`: aborts if a process cmdline mentions `opencode` (pgrep, excluding the tool itself), re-verifies the copy read-only, snapshots the live DB with `sqlite3 .backup` to `$OCED_BACKUP_DIR/pre-shrink/opencode.pre-shrink-<ts>.db` (keeps only the most recent copy), swaps with an atomic `mv`, drops the stale `-wal`/`-shm` and rolls back if the new DB fails `integrity_check`. `--swap` is the ONLY path that writes the live DB, and only on explicit request. **`oced_shrinks`** — manager of the produced copies: `shrinks list [--tsv]|view <stamp> [--json]|verify [--tsv] [--yes]|remove <stamp> [--yes]|prune <N>` over `$OCED_BACKUP_DIR/shrink/<stamp>/` (`--tsv` emits the TSV `stamp<TAB>display` rows = the single source for the menu picker). **TWO screens, two widths**: `list` is a COLUMN — `<date>  <tag>  <kept>/<total> kept  <before> -> <after> -N%`, the tag from `plan.py rule-tag`, ONE size expression (the row used to print the sizes three times) and the copy's own state only when it is anomalous (`(swapped/no copy)`); `view` is a DETAIL screen shaped like `exports view` (`== Shrink copy: <stamp> ==` then `sessions:`/`size:`/`selection:`/`criteria:`/`reasoning:`/`date:`/`db:`/`integrity:`/`freshness:` + the per-table removals + the files) and it carries the FULL criteria sentence plus the selected ids **capped at 8** with `… N more` — the sentence and the ids are what a column cannot hold, so they live here and nowhere else. `--json` stays the machine view: `shrink.json` verbatim, byte for byte, no banner. A legacy `shrink.json` with no `.selection` falls back to its cut criteria instead of losing the cell. Stale checks live in **one** helper: `o_shrink_stale <shrink.json>` (echoes a warning/returns 1 when the live DB is newer, or when a legacy shrink.json lacks `sessions.max_updated` — unverifiable is also flagged); `menu.sh` and `oced_shrinks_verify` call it — the swap/remove paths ask it about the ONE picked copy, while `shrinks verify` asks it about **every** copy (a `stale` `--tsv` row is keyed by that copy's stamp, and an orphan dir is reported once, as an orphan, never also as stale). Helpers `shrinks_dir`/`shrinks_runs_find` (dirs, newest first)/`shrinks_stamp_human` (`YYYYMMDD-HHMMSS` → human)/`shrinks_run_row` (one TSV row: the compact display of the copy, `tag=` initialised because `local` does not, and `${OCED_SHRINK_PRESETS:-}` because under `set -u` a bare reference kills the subshell and silently empties the tag).

## Schema rules (opencode.db)

- `session`: `parent_id` (subagent when non-empty), `agent` (build/explore/plan), `model`, `directory`, `time_compacting`, `tokens_*`, `cost`, `share_url`.
- `part.data.type` ∈ `text | file | step-start | reasoning | tool | step-finish | patch | compaction`.
- Tool call: `part.data` → `state.input.command` (tool), `state.input.arguments`, `state.output` (truncatable).
- `message.data.summary.diffs` — per-message change summary (`--summary-diffs`); `summary` can be `true` (bool), not only an object.
- Compactions: parts `type='compaction'` are only markers (`auto`, `overflow`, `tail_start_id`); the compacted-context **digest** is the `text` part of the next message with `data.mode='compaction'`.
- Session pickers must ignore the sqlite `-column` separator line (rows are filtered by `$1 ~ /^ses_/`).
- Config precedence is **environment > conf file > per-file default** (that default is `~/.config/opencode-db/<file>` if present, else the repo-shipped copy when running portably, else the built-in; `common.sh` snapshots env vars before sourcing `$OCED_CONF`). Keep it that way: never let the conf clobber an explicitly exported variable.

## Known pitfalls

- **SIGPIPE/pipefail**: never use `cmd | grep -q PATTERN` in tests or modules when `cmd` is a long-running subprocess; grep closes the pipe on match and the producer dies with 141. Capture first: `out=$(cmd); printf '%s' "$out" | grep -q PATTERN`.
- `model` may already be serialized as JSON (don't double-encode).
- Newlines inside JSON after `json_each`/diagonals are escaped before `data:json_each`; use `json_quote` for raw dumps.
- `set -euo pipefail` in bash: pipelines with `grep -q` may return 141 (see above).
- Local `trap` EXIT inside functions: `trap - EXIT` before `return` so the caller's trap isn't cancelled.
- **`shrink --swap`**: the EXIT trap removing `$snap` must be cleared (`trap - EXIT`) BEFORE the swap moves the snap into `$OPENCODE_DB`, or the trap would delete the live DB on exit. The swap safety copy is written to `$OCED_BACKUP_DIR/pre-shrink/` (not `$OPENCODE_DB.pre-shrink-*`); stale checks use `o_shrink_stale` on `sessions.max_updated`, which the current `shrink.json` format records — older copies without it are flagged as unverifiable.
- `o_effective_db` is memoized: `o_resolve_db` must run in the **parent** shell (the dispatcher calls it; `o_db_exists` calls it directly). Never resolve a backup only inside `$(...)` (command substitution = subshell: the decompressed temp would be re-created per call and never cleaned). The dispatcher sets `trap 'o_cleanup_tmp' EXIT` to remove the decompressed `.gz` temp.
- Paths and file names: `safe_filename` strips `@()[]` etc.

## Deploy

- `install.sh` — copies `src/` (+`uninstall.sh`, `LICENSE`) to `~/.local/share/opencode-db-exporter` (no tests/docs/`generated`/schema artifacts: the tool never reads them at runtime), symlinks `~/.local/bin/opencode-db` → `src/opencode-db.sh`, creates conf from the shipped `opencode-db.conf` if missing (permissions 600) and presets from the shipped `presets.json` + shrink presets from the shipped `shrink-presets.json` if missing (permissions 600).
- `uninstall.sh [--all] [--yes]` — removes the installed code + shim; keeps conf/backups/exports unless `--all` (the keep-`backups`/`exports` branch uses a whitelist find under `$PREFIX`, not a reinstall list).
- Config: `~/.config/opencode-db/opencode-db.conf` (600) + `~/.config/opencode-db/presets.json` (600) + `~/.config/opencode-db/shrink-presets.json` (600). Dependencies are self-managed via `opencode-db deps`.
