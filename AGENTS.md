# AGENTS.md — opencode-db-exporter

Bash+python tool to read, back up and export the local opencode SQLite database. Never write to
the opencode DB: all access uses `mode=ro` (bash: `file:$DB?mode=ro`; python: `sqlite3.connect(f"file:{db}?mode=ro", uri=True)`).

## Commands that MUST be run after editing code

```bash
# Shell syntax (every script has #!/usr/bin/env bash)
for f in modules/*.sh modules/menu/*.sh install.sh uninstall.sh tests/*.sh; do bash -n "$f"; done

# Python
python3 -m py_compile modules/exportlib/*.py modules/shrinklib/*.py

# Smoke tests against a fake DB (never touches real data)
bash tests/export_smoke.sh        # must report 0 FAIL
bash tests/menu_flow.sh           # fzf menu logic (fzf stubbed) -> must report 0 FAIL
```

When flags change (`exportlib/flags.py` for exports, `shrinklib/flags.py` for shrink — each is the SSoT), regenerate BOTH artifacts and validate:
```bash
python3 scripts/generate_schema.py                 # rewrites generated/{presets,shrink}.schema.json
python3 scripts/generate_schema.py --docs          # rewrites generated/{flags-table,shrink-flags-table}.md
python3 tests/validate_schema.py generated/presets.schema.json presets.json.example
python3 tests/validate_schema.py generated/shrink.schema.json shrink-presets.json.example
```
Deploy always syncs `generated/` too, so the installed prefix (offline, no docs/) still has
the artifacts for the smoke suite.

## Structure

- `modules/opencode-db.sh` — CLI dispatcher: `status | version | list | info | compactions | backup | backups | export | exports | shrink | shrinks | deps | menu | help`. Accepts a global `--from-backup <file>` (before the subcommand) that sets `OCED_FROM_BACKUP` so every read command uses a stored backup as source. Sources common.sh + view.sh + backup.sh + export.sh + exports.sh + deps.sh; menu.sh is sourced on demand.
- `modules/common.sh` — config (`OPENCODE_DB`, `OCED_OUT`, `OCED_BACKUP_DIR`, `OCED_CONF`, `OCED_ACTIVITY_LOG`, `OCED_FROM_BACKUP`, `OCED_PRESETS`, `OCED_SHRINK_PRESETS`, `OCED_VERSION`) and helpers `o_q`, `o_die`, `o_ts`, `o_now_utc`, `o_check_deps`, `o_resolve_db`/`o_effective_db` (memoized: resolves live DB or backup, gunzips `.gz` to one temp file), `o_cleanup_tmp`, `o_backup_aligned`. `o_q` is ALWAYS readonly: `sqlite3 "$(o_db_uri)"`. `load_conf` snapshots env vars BEFORE sourcing `$OCED_CONF` (env > conf) for `OPENCODE_DB OCED_OUT OCED_BACKUP_DIR OCED_COMPRESS OCED_LOG OCED_ACTIVITY_LOG OCED_FROM_BACKUP OCED_PRESETS OCED_SHRINK_PRESETS`.
- `modules/view.sh` — status/version/list/info/compactions (reads only); helpers `o_version_block`/`o_schema_probe`/`o_deps_report`; `status` ends with "Version / schema:" + "Dependencies:" sections; `list` takes `--order created-asc|created-desc|updated-asc|updated-desc` (whitelisted in `OCED_LIST_ORDERS`, default `created-asc` = unchanged; the ordering column always falls back to `time_created` as the tie-break); `version` prints tool version (opencode-db) + opencode CLI version (max `session.version`) + schema probe (`OCED_EXPECTED_TABLES`/`OCED_EXPECTED_COLUMNS`), returning non-zero when tables/columns are missing; `compactions <id> show [last|N|all]` prints the compacted-context digest from the following `mode=compaction` message.
- `modules/backup.sh` — `sqlite3 "$DB" ".backup <snap>"` (WAL-safe), optional gzip, sha256, atomic `manifest.json` (jq), `backups list/verify/prune`.
- `modules/exportlib/` (Python package: `util.py`/`config.py`/`sanitize.py`/`presets.py`/`db.py`/`render.py`/`transcript.py`/`faithful.py`/`memory.py`/`writers.py`/`cli.py` + **`flags.py`** — the single source of truth for every export flag: name/type/choices/default/products/description (CLI `--flag` form in `cli.py` (incl. the `--filter|--sessions|--last|--since` mutex group, and the CLI-only `--out`/`--last`/`--since` in `CLI_ONLY_KEYS`), presets key validation in `presets.py`, `generated/presets.schema.json` AND `generated/flags-table.md` are generated from it by `scripts/generate_schema.py`, menu annotations via `exportlib/flags.py --annotate "key=value,…"` used by `oc_annotate_flags`; the `export products:`/`export flags:` block of `opencode-db help` is emitted by `flags.py --help-exports` (products from `PRODUCT_HELP`, flags from `FLAG_HELP` in dict order — `help()` in `opencode-db.sh` calls it with a static fallback); to add/modify a flag edit `FLAGS`, then regenerate) + **`plan.py`** — the single Python place that answers "what will this export produce?" for any profile (product keyword OR named preset): `resolve()` returns the full JSON plan (products, per-product intro/flags/bits, has_json/has_sanitize, descr/purpose) and a CLI bridge (`rows`/`names`/`products` (+`--legend`)/`descr`/`purpose`/`legend`/`resolve`/`plan`, exit 1 = nothing to produce) that runs the `menu.sh` preset helpers — `oc_preset_rows`/`oc_preset_descr`/`oc_preset_purpose`/`oc_preset_legend`/`oc_export_plan` are thin shells pinning `OCED_PRESETS` through `oc_plan_py` and delegating to it (no more jq in the menu; `oc_pick_product` is gone — the menu is preset-only, but `products`/`products --legend` stay as the API surface for the CLI and tests; products + plans + intros are edited in `flags.py`/`plan.py`, not in `menu.sh`); `PRODUCT_INTRO`/`PRODUCT_KEYWORDS`/`PRODUCTS` live in `flags.py`); `modules/exportlib/cli.py` is the self-bootstrapping CLI entry (running it directly adds `modules/` to sys.path — the old `modules/export.py` shim is gone; `export.sh` forwards to `python3 "$SCRIPT_DIR/exportlib/cli.py"`)) — products `transcript|memory|compactions` (`full` accepted as an alias of `transcript`); no `all` meta-profile, no `no-calls`/`text-only`; `--filter`, `--sessions ID[,ID…]` (exact session ids, `WHERE s.id IN (…)`), `--sub separate|inline|omit`, **subagent inclusion** `--no-subagents` / `--no-orphan-subagents` (both `products=["*"]`, applied to the selected set BEFORE the hierarchy is resolved; a *subagent* = non-empty `parent_id` whose parent row still exists (`all_session_ids()`), a session whose parent is gone is an *orphan* = a root and is never hidden; `--no-subagents` drops every subagent for ALL products, `--no-orphan-subagents` drops a selected subagent whose parent is not exported (fixpoint over nested chains) instead of promoting it to a root — the DEFAULT keeps it standalone, which is the "only that one subagent" use case; both die with an explanation when nothing is left; `metadata.json` gains `.no_subagents`/`.no_orphan_subagents`/`.subagents_hidden` = how many the flags actually dropped from the MATCHED set, and `index.md` only grows the `Subagents` row when a flag set it), `--tool-output full|truncated|omit`, `--patch full|omit`, `--mark-compactions`, `--summary-diffs`, `--no-reasoning`, `--role all|user|assistant` (a flag, NOT a preset; `memory` ignores it, documented in its index); `--json` (faithful archive per session, native `{info, messages:[{info, parts}]}` shape, `info.tokens.backfilled`); `--sanitize` (recursive regex redaction **in memory, on native types, before serializing** — `sanitize_json` walks `dict`/`list`/`str`; markdown sanitizes each string at render time; never post-processes the final file: high-confidence prefixes only `sk-`/`sk-ant-`/`ghp_`/`gho_`/`github_pat_`/`xox[baprs]-`/`AIza`/`AKIA`/JWT (`eyJ…`)/`Bearer`/private PEM keys (multiline, `re.S`); generic `key=value`/env-var-name patterns are deliberately EXCLUDED to avoid false positives); **`snapshot: fresh`** — a SINGLE-preset-only workflow flag (`SINGLE_ONLY_KEYS`; never per-product/bundle): the export doubles as a reference archive, so the CLI warns (`_backup_aligned` — same triple as the menu's `o_backup_aligned`) when no backup exists or the last one diverged from the live DB, and the menu offers to create a fresh backup first; skipped under `--from-backup`; **token backfill** — sessions whose `tokens_*`/`cost` row is 0/NULL get their totals summed from `part` rows `data.type='step-finish'` (`tokens.input/output/reasoning/cache.{read,write}` + `cost`), in-memory, flagged `tokens_backfilled`; `memory` adds `--cap N` (0 = unlimited, default) + `--files` (touched files from tool inputs `path/filePath/file_path` and `+++ b/` patch headers) and writes `corpus.jsonl` **streamed line by line** (one root+subagents per line, `flush()` per root — never accumulates the corpus in RAM; prints a `--cap` hint past ~50 MB with unlimited text); help `digests_for`/`touched_files` — the SAME compaction source used by `view.sh` and the `compactions` product. **Named presets** — `OCED_PRESETS` JSON file is the source of truth for CLI + menu (contract: `generated/presets.schema.json`, docs: `docs/schemas.md`): `export <name>` auto-resolves (`name` = product keyword → product; else known preset → `apply_preset()` merges its keys over argparse defaults validating choices/types with `die()`; else `ap.error` lists products+presets); allowed keys `product|sub|no_subagents|no_orphan_subagents|tool_output|tool_input_limit|tool_output_limit|patch|role|no_reasoning|mark_compactions|summary_diffs|json|sanitize|cap|files` + selection `filter` (LIKE) **or** `sessions` (ids, not both); **`--last N`/`--since DATE` are CLI-ONLY selection rules** (in `CLI_ONLY_KEYS` with `out`, so the generated schema rejects them: their set changes every run, so no plan can pin one) — exactly ONE selection rule per run in one argparse mutex group (`--filter|--sessions|--last|--since`), `_pos_int`/`_iso_date` validate at the command line (`--last 0`/`abc` and a non-`YYYY-MM-DD` date are refused), `load_sessions` implements them (`--last` ranks ROOTS by `time_updated` and closes over descendants with a recursive CTE, like `shrink --keep N`; `--since` is a plain window), and `util.selection_rule()`/`selection_label()`/`selection_meta()` are the ONE description of the rule (metadata `.selection`, the `index.md` `Selection` row, the "matched nothing" error, and the `plan.py` menu queries); ***bundle presets** use `products` = `{product: {flags}}` (transcript|memory|compactions, exclusive with `product`, selection stays top-level/shared) — `run_bundle()` in `cli.py` computes one shared collision-free stamp and re-executes `exportlib/cli.py <product> --stamp <shared> --preset-name <main>` per product (unchanged single-product pipeline: own index.md + metadata.json, a stamp-root index.md ties the bundle; `exports list` aggregates as `transcript+memory`). **CLI wins over the preset***: explicit `--filter`/`--sessions` clobber the whole preset selection (`cli_selection`), any explicit flag wins (`flag_in_argv`; preset keys are underscored but map to dashed flags via `_flag()`). `metadata.json` records `.preset`/`.sessions_selected`. Writes `index.md` + `metadata.json` per run (`metadata.json.role`, `.json`, `.sanitize`, `.reasoning`, `.tokens_backfilled`; memory: `.touched_files` bool + `.files` produced list — never a shared key). **Contract hardening** (docs/schemas.md): dates ISO-8601 UTC via `ts_iso` (`YYYY-MM-DDTHH:MM:SSZ`); absent values `null` in machine artifacts (corpus/faithful/metadata), `""` only in markdown; `model_str` normalizes a JSON-serialized model to its plain id (one form); corpus lines carry `schema_version: 1` (bump on breaking shape change); corpus `messages`/`tools`/`compactions` count the ROOT session only.
- `modules/shrinklib/` (Python package: `__init__.py`/`config.py`/`flags.py`/`presets.py`/`plan.py`; `py_compile` it in the mandatory suite) — the shrink mirror of exportlib, split in **two disjoint families**: **session SELECTION** (CLI flags `keep`/`older_than`/`since`/`keep_all`/`keep_sessions`/`discard_sessions` — exactly ONE per invocation, `keep`=10 by default; NOT preset keys) and **OPERATIONS** (`strip_reasoning`; the only keys a recipe may carry). **`flags.py`** is the SSoT: `SHRINK_FLAGS` (all 7) + `KEEP_RULE_KEYS` (selection) + `OPERATION_KEYS`/`SHRINK_PRESET_KEYS` (ops) + `DEFAULT_SHRINK_PRESETS` (**lean**=strip, **quiet**=prune+vacuum) + `SHRINK_PRESET_PURPOSE` + `help_main_shrinks()` (the `shrink presets:` block of `opencode-db help` comes from `shrinklib/flags.py --help-shrinks`, static fallback in the dispatcher) + `usage_main_shrinks()`; `generated/shrink.schema.json` (a recipe = object with only the op keys, NO oneOf keep rule) AND `generated/shrink-flags-table.md` (two tables: selection CLI-only + operations) are generated from it by `scripts/generate_schema.py`; `config.py` has `default_shrink_presets` (env `OCED_SHRINK_PRESETS` — an EMPTY value counts as unset, else `Path("")` would resolve to the CWD — > `~/.config/opencode-db/shrink-presets.json`); `presets.py` loads/validates the file (a keep rule inside a recipe DIES pointing at the matching CLI flag; unknown keys die; strip must be bool) and merges it OVER the built-ins — `bake_args` maps a name to operation flags (`--strip-reasoning`), unknown → `die` + known list; `selection_lines`/`op_lines`/`rule_lines` render the human criteria; **`plan.py`** is the single source for the shrink menu (mirror of exportlib/plan.py): `rows` (built-ins + file recipes, `__PRESET_<name>\t<name>  <operations>`), `names`, `descr`, `purpose`, `plan`, `bake`, **`ops-flags <strip>`**/**`op-lines <strip>`** (a TOGGLED operation set, for the menu), `list-presets` and `rule-line <rule> [value] [strip 0|1]` (human criteria for the bash engine's final resolved rule — `shrink.sh` never builds those phrases itself). It has NO `selection` command anymore (the menu no longer derives a selection from a recipe). Bash calls it via `python3 "$SCRIPT_DIR/shrinklib/plan.py"` with `OCED_SHRINK_PRESETS` pinned (= `oc_shrink_py` in menu.sh). `flags.py` is self-bootstrapping (adds `modules/` to sys.path) and serves BOTH `--help-shrinks` (the `shrink presets:` block of `opencode-db help`) AND `--usage` (the full `opencode-db shrink --help` text that `oced_shrink_usage` delegates to).
- `modules/shrink.sh` — `oced_shrink`: a **recipe** (named OPERATIONS from shrinklib: built-ins lean/quiet + `$OCED_SHRINK_PRESETS`; the first non-flag token is baked via `shrinklib/plan.py bake` → `--strip-reasoning`; the python error is surfaced verbatim, falling back to a generic unknown-recipe hint) **or nothing** (no recipe = default selection, no operation) + raw flags `--keep N`/`--older-than DAYS`/`--since DATE`/`--keep-all`/`--keep-sessions ID[,ID]`/`--discard-sessions ID[,ID]`/`--strip-reasoning`/`--dry-run`/`--list-presets` over a copy (line 2: `set -uo pipefail`); exactly ONE keep rule applies (last one wins). The kept set is closed (a kept session keeps its parents/subagents); `--discard-sessions` removes the listed ids + their descendants (the discard set is descendant-closed, so FK-safe by construction) and prints a hint to `export memory --sessions <ids>` first. shrink.json records criteria/counts/per-table `removed`/`stripped_reasoning`/integrity + `selection` (JSON `{"rule": "keep_sessions", "ids": [...]}`) + `sessions.max_updated` (the copy's newest `session.time_updated`, needed by the stale check). The rest of the pipeline is unchanged: prunes session-bound tables (message/part/todo/session_message/session_share/session_context_epoch/session_input) + `event`/`event_sequence` aggregates (`aggregate_id LIKE 'ses_%'`); optional strip-reasoning removes `part` rows whose `data` JSON has `type=reasoning`; then `integrity_check` (ok) + `foreign_key_check` (0 rows) BEFORE storing `opencode.shrunk.db`. The human `criteria` line + the `--help` block are single-sourced in python (`plan.py rule-line` / `flags.py --usage`). `--swap [--yes]` (opt-in, incompatible with `--dry-run`) replaces the LIVE DB via `oced_shrink_swap`: aborts if a process cmdline mentions `opencode` (pgrep, excluding the tool itself), re-verifies the copy read-only, snapshots the live DB with `sqlite3 .backup` to `$OCED_BACKUP_DIR/pre-shrink/opencode.pre-shrink-<ts>.db` (keeps only the most recent copy), swaps with an atomic `mv`, drops the stale `-wal`/`-shm` and rolls back if the new DB fails `integrity_check`. `--swap` is the ONLY path that writes the live DB, and only on explicit request. **`oced_shrinks`** — manager of the produced copies: `shrinks list [--tsv]|view <stamp>|verify [--tsv] [--yes]|remove <stamp> [--yes]|prune <N>` over `$OCED_BACKUP_DIR/shrink/<stamp>/` (`--tsv` emits the TSV `stamp<TAB>display` rows = the single source for the menu picker). Stale checks live in **one** helper: `o_shrink_stale <shrink.json>` (echoes a warning/returns 1 when the live DB is newer, or when a legacy shrink.json lacks `sessions.max_updated` — unverifiable is also flagged); `guide.sh`, `menu.sh` and `oced_shrinks_verify` all call it. Helpers `shrinks_dir`/`shrinks_runs_find` (dirs, newest first)/`shrinks_stamp_human` (`YYYYMMDD-HHMMSS` → human)/`shrinks_run_row` (one TSV row aggregating shrink.json + the copy size).
- `modules/menu.sh` — fzf menu (`run_menu`/`choose_action`/`oc_fzf_sel`); root: status/backups/shrinks/sessions/**export**/exports/guide/help. **Root header**: `run_oc_menu` passes `--refresh-cb oc_root_status` so `ACTION_STATUS` (DB/sessions/WAL/backup/exports counts) is recomputed on every root loop — never stale after an action. Pickers: `oc_backups_picker` single-mode (`__CREATE__` → `__DELETE_ALL__` → `__KEEP_NEWEST__` → per-backup rows; selecting a row deletes it; `backups verify` stays CLI-only), `oc_sessions_picker` details-only (info+compactions), `oc_shrinks_picker` **create + manage in one entry** (rows `__CREATE__` first, then `__SWAP__` (destructive — pick a copy, `o_shrink_stale` warning, `oc_confirm_typed "confirm"`, `oced_shrink_swap`), then `__TOGGLE__` view/remove, plus `__VERIFY__` = `shrinks verify`; remove mode adds `__DELETE_ALL__`/`__KEEP_NEWEST__` + per-run rows — deleting a stale/unknown-freshness copy warns via `o_shrink_stale` first; selecting a row views `shrinks view <stamp>` or removes with confirmation; rows come from the shrink.sh helpers `shrinks_runs_find`/`shrinks_run_row` — same source as `shrinks list --tsv`, no duplicated jq), `oc_session_picker` (in `modules/menu/core.sh`) is the GENERIC multi-mark picker (cfg nameref: `roots_only`/`title`/`header`/`order`/`order_mode`/`make_label`/`make_action`/`empty_guard_msg`/`get_sub_count` and — for the export only — **`get_sub_ids`**, which adds the `__SUBS__` row `subagents: shown ⇄ hidden`: a hidden subagent is not RENDERED, so it can never be marked nor reach the CSV (the cascade is structural) and the 3rd arg `hide_subs` is passed to `make_action` **only when that row exists**, keeping the shrink callback arity intact; `oc_toggle_row` takes an optional 3rd key for that second switch). `oc_export_picker` **preset-ONLY** (rows `__PRESET_<name>` served by `exportlib/plan.py rows`; bundle presets render `[transcript+memory]`; if `$OCED_PRESETS` is missing it prints setup guidance — `cp "$SCRIPT_DIR/../presets.json.example" "$OCED_PRESETS"` — plus the raw CLI as fallback: **there is NO manual session→product flow anymore**, `oc_pick_product`/`oc_export_flow`/`oc_export_manual_picker` are gone and `oc_export_manual_rows` was renamed `oc_selection_rows`). **The selection is run-time state**: after any preset, `oc_preset_run` reuses the session rows — marking EVERY session runs the preset as configured (no `--sessions`), a partial selection becomes `export <name> --sessions <csv>`; a hidden-subagent run also pins `--no-subagents` (`oc_export_sub_ids` serves the picker, `oc_export_sub_counts` the badges) so the roots-only guarantee survives the "all marked" path, and the confirm names it in its `Menu adds:` row (CLI-wins, shared in a bundle); in SHOWN mode a subagent is an ordinary row with its OWN mark, so unmarking its session leaves it in — the engine then exports it standalone, which the confirm must SAY: `oc_export_standalone_subs <csv>` (reuses `oc_export_sql_ids`; the `EXISTS (parent row)` guard makes an orphan a root, never a standalone subagent) gated on `hide != 1` (hidden mode puts no subagent in the CSV, and "all marked" has every parent selected, so both are silent by construction); a `snapshot: fresh` preset first offers a fresh backup when `o_backup_aligned` is not aligned. **`oc_preset_run` states the EFFECTIVE selection, never the intent**: it asks `plan.py selection <name>` (the pinned `filter`/`sessions` as a human phrase) and `plan.py subagents <name>`, then `oc_export_confirm <preset> <sessions> <menu-adds> <note>` prints `Sessions:` (all marked + no pinned selection → `all N sessions in the DB`; all marked + pinned → `filter "%x%" (from the preset) — your N marks are not used`; partial → `the N sessions you marked (the menu overrides the preset: …)`), `Menu adds:` (ONLY the menu's own flags, i.e. `--no-subagents`) and an optional `Note:` (standalone subagents, or a preset that already drops subagents so the switch cannot widen it). The old `Filter: (preset as configured)` + duplicated `Spec:` CSV/descriptions are GONE; the **Will produce:** block still carries the per-product descriptions + effective flags and the sanitize caveat. **`oc_pick_shrink`** (the create entry of the shrinks picker) is a **3-step wizard** and nothing else — `__CUSTOM__`/`__DRYRUN__`/`__SESSIONS__` are GONE: (1) `oc_shrink_sessions_pick` opens the **sessions picker on ROOT sessions only** (`session_rows --root`; a subagent always follows its root, so it never gets a row, and an orphan whose parent is gone IS a root): `[x]` = survives, default ALL marked; `__MAKE__` = CONTINUE (not "build"): all marked → `--keep-all`, unmarked roots → `--discard-sessions <csv>`, nothing marked → guard "EMPTY database" and loop. The ONLY bulk rows are `mark all`/`unmark all`: the recency rows (`__LAST__`/`__OLDEST__`/`__DAYS__`) and their `oc_read_int` helper are GONE (a row that re-computes "the N newest" at run time is a selection, not a marking — recency is `--last`/`--since` on the CLI), and the header is ONE line of live state recomputed per render (`N/M marked · order · ESC: back`, plus a caveat line only when a switch has a consequence the rows cannot show). Rows open sorted `updated-desc` (newest used first) plus an `__TOGGLE__` row that flips to `updated-asc`: the rows are re-read every render and the marks live in a 1/0 assoc array (never unset, so an explicit unmark survives a re-sort). (2) `oc_shrink_ops_pick <sel-args>` — the **recipe and nothing else**: the rows from `oc_shrink_rows` (`shrinklib/plan.py rows`), no toggle and no "continue" row; any row is a named ops-only recipe whose operations are baked and taken straight to the plan (recipes compose in the file, not in the picker). `oc_shrink_confirm_run <runargs> <strip> <sel-args> [recipe]` prints the recipe purpose + the effective `Command:` and returns 2 when declined (the caller loops back to the recipes), 130 on ESC (`oc_shrink_sessions_pick` climbs one level). (3) `oc_shrink_confirm_run <runargs> <strip> <sel-args>` — the **read-only plan**: exact counts on the LIVE DB with the engine's own predicates (kept roots+subagents, discarded cascade, rows per table, reasoning, current size via `o_shrink_sql_ids` + a recursive `WITH RECURSIVE` closure), the `export memory --sessions` offer when discarding, then the y/N gate and `run_oced_tool shrink $runargs`. `oc_shrink_sub_counts` supplies the `(N sub)` badge per root (recursive, `-separator $'\t'`). ESC at operations climbs back to the sessions picker with the marks intact. `oc_confirm_typed <word>` is the hard gate for destructive swaps (reused by guide.sh), `oc_exports_picker` with a mode toggle (`oc_toggle_row`, key `__TOGGLE__` view/remove) — **no TAB multi-select anywhere**, bulk ops are their own rows. Rows are TSV `key<TAB>display` (`--with-nth=2..`); single-row actions are per-file. **No manual variant/custom/bundle rows in the export picker**: export tuning lives in the presets file (`OCED_PRESETS`) or on the CLI. **`shrink` creation lives in the shrinks picker** (LIVE DB, own snapshot, `--from-backup` does NOT affect it) — no `__SHRINK__` row in backups: the 3-step wizard above (sessions → operations → read-only plan) and nothing else; ESC cancels/climbs one level.
- `tests/make_fake_db.sh` — fake DB (6 sessions, orphan/nested subagents, compaction marker + digest message, long tool outputs, summary:true edge case, step-finish with tokens/cost for the backfill, tool with a fake API key for `--sanitize`; also the empty real tables so the `version` schema probe passes). ## Schema rules (opencode.db)

- `session`: `parent_id` (subagent when non-empty), `agent` (build/explore/plan), `model`, `directory`, `time_compacting`, `tokens_*`, `cost`, `share_url`.
- `part.data.type` ∈ `text | file | step-start | reasoning | tool | step-finish | patch | compaction`.
- Tool call: `part.data` → `state.input.command` (tool), `state.input.arguments`, `state.output` (truncatable).
- `message.data.summary.diffs` — per-message change summary (`--summary-diffs`); `summary` can be `true` (bool), not only an object.
- Compactions: parts `type='compaction'` are only markers (`auto`, `overflow`, `tail_start_id`); the compacted-context **digest** is the `text` part of the next message with `data.mode='compaction'`.
- Session pickers must ignore the sqlite `-column` separator line (rows are filtered by `$1 ~ /^ses_/`).
- Config precedence is **environment > conf file > default** (`common.sh` snapshots env vars before sourcing `$OCED_CONF`). Keep it that way: never let the conf clobber an explicitly exported variable.

## Known pitfalls

- **SIGPIPE/pipefail**: never use `cmd | grep -q PATTERN` in tests or modules when `cmd` is a long-running subprocess; grep closes the pipe on match and the producer dies with 141. Capture first: `out=$(cmd); printf '%s' "$out" | grep -q PATTERN`.
- `model` may already be serialized as JSON (don't double-encode).
- Newlines inside JSON after `json_each`/diagonals are escaped before `data:json_each`; use `json_quote` for raw dumps.
- `set -euo pipefail` in bash: pipelines with `grep -q` may return 141 (see above).
- Local `trap` EXIT inside functions: `trap - EXIT` before `return` so the caller's trap isn't cancelled.
- **`shrink --swap`**: the EXIT trap removing `$snap` must be cleared (`trap - EXIT`) BEFORE the swap moves the snap into `$OPENCODE_DB`, or the trap would delete the live DB on exit. The swap safety copy is written to `$OCED_BACKUP_DIR/pre-shrink/` (not `$OPENCODE_DB.pre-shrink-*`); stale checks use `o_shrink_stale` on `sessions.max_updated`, which the current `shrink.json` format records — older copies without it are flagged as unverifiable.
- `o_effective_db` is memoized: `o_resolve_db` must run in the **parent** shell (the dispatcher calls it; `o_db_exists` calls it directly). Never resolve a backup only inside `$(...)` (command substitution = subshell: the decompressed temp would be re-created per call and never cleaned). The dispatcher sets `trap 'o_cleanup_tmp' EXIT` to remove the decompressed `.gz` temp.
- Paths and file names: `safe_filename` strips `@()[]` etc.

## Deploy

- `install.sh` — copies modules+tests+scripts+generated (+`uninstall.sh`, `presets.json.example`, `shrink-presets.json.example`) to `~/.local/share/opencode-db-exporter`, symlinks `~/.local/bin/opencode-db` → `modules/opencode-db.sh`, creates conf from `opencode-db.conf.example` if missing (permissions 600) and presets from `presets.json.example` + shrink presets from `shrink-presets.json.example` if missing (permissions 600).
- `uninstall.sh [--all] [--yes]` — removes the installed code + shim; keeps conf/backups/exports unless `--all` (the keep-`backups`/`exports` branch uses a whitelist find under `$PREFIX`, not a reinstall list).
- Config: `~/.config/opencode-db/opencode-db.conf` (600) + `~/.config/opencode-db/presets.json` (600) + `~/.config/opencode-db/shrink-presets.json` (600). Dependencies are self-managed via `opencode-db deps`.
